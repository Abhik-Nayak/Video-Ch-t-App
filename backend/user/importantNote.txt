Bonus Tip:

"In a real-world scalable app, never send emails or long-running tasks directly in the controller.
Always offload them to a queue using tools like RabbitMQ, BullMQ, or Kafka.
This makes your app faster, cleaner, and production-ready."


How the Flow Works:

1. User hits login API (/login)

- A 6-digit OTP is generated.
- The OTP is stored in Redis.
- Then, we send a message to RabbitMQ (to the send-otp queue), which contains:

{
  "to": "user@example.com",
  "subject": "Your OTP Code",
  "body": "Your OTP is 23456. It is valid for 5 minutes."
}


2. Producer — Publishing to RabbitMQ

Inside the loginUser controller, we use a function like:

publishToQueue("send-otp", message)

This pushes the OTP email job to RabbitMQ.


3. Consumer — Worker picks the job

In a separate file (usually consumer.ts), we run a background worker which:

- Listens to the send-otp queue.
- When a message arrives, it reads the email details and uses nodemailer (or any mail service) to send the email.
- After success, it acknowledges the message:channel.ack(msg)


Why Use RabbitMQ?

- Non-blocking: The user doesn't have to wait for the email to be sent — the API responds instantly.
- Scalable: We can send thousands of emails by running multiple consumers (workers).
- Reliable: If email fails, we can requeue the message and try again.
